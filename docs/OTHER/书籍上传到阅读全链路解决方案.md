# 书籍上传到阅读全链路解决方案

## 1. 问题背景

电子图书馆需要支持管理员上传多种格式的电子书（TXT、DOC/DOCX、PDF 等），统一转换为 EPUB 格式供客户端阅读。同时需要支持"免费预览前 5%"功能，涉及多系统协同（MySQL、Elasticsearch、S3、Calibre 转码服务），是一个典型的分布式异步处理场景。

## 2. 核心难点

| 难点 | 说明 |
|------|------|
| **格式多样性** | 用户上传格式不固定（TXT/DOC/PDF/EPUB），需要统一转码为 EPUB |
| **转码工具选型** | POI、Calibre、LibreOffice 各有取舍 |
| **异步处理** | 转码是耗时操作（PDF 转 EPUB 可能数分钟），不能阻塞 HTTP 请求 |
| **分布式存储** | MySQL 存元数据、S3 存全文、ES 存预览内容，三者需要保持一致性 |
| **预览鉴权** | 客户端使用 epub.js 阅读时，需要拦截请求判断是临时预览还是已借阅 |
| **临时文件管理** | 转码中间产物需要临时存储，完成后需要清理 |

## 3. 转码工具选型 Trade-off

### 方案 A：Apache POI

**适用场景**：仅处理 Office 格式（DOC/DOCX/XLS/PPT）

| 维度 | 评价 |
|------|------|
| 优点 | Java 原生、无外部依赖、集成简单 |
| 缺点 | 不支持 PDF 转 EPUB、排版还原差、图片处理复杂 |
| 性能 | 内存占用高，大文件易 OOM |

### 方案 B：LibreOffice

**适用场景**：DOC → PDF 中间转换

| 维度 | 评价 |
|------|------|
| 优点 | 排版还原度高、支持格式多 |
| 缺点 | 需要安装 LibreOffice、启动慢（headless 模式）、不适合高并发 |
| 性能 | 每次转换需启动进程，约 3-5 秒 |

### 方案 C：Calibre ebook-convert

**适用场景**：最终转码为 EPUB

| 维度 | 评价 |
|------|------|
| 优点 | 专业电子书转换工具、支持格式最全（TXT/DOC/PDF/HTML → EPUB）、保留目录结构、自动处理编码 |
| 缺点 | 需要安装 Calibre、依赖 Python 环境、转换速度慢（大文件可能数分钟） |
| 性能 | 单次转换 10-60 秒，取决于文件大小和格式 |

### 最终选型：Calibre + LibreOffice 组合

```
用户上传文件
    │
    ├── TXT/HTML/EPUB  ──→ 直接用 Calibre ebook-convert
    │
    └── DOC/DOCX       ──→ LibreOffice 先转 PDF ──→ Calibre 转 EPUB
```

**理由**：
- Calibre 是电子书转换领域的事实标准，对 EPUB 输出质量最高
- LibreOffice 作为 DOC/DOCX → PDF 的中间转换器，排版还原度优于 POI
- 两者都是成熟的开源工具，社区活跃，无需自研
- 通过异步任务队列解耦，转码慢不影响用户体验

## 5. 存储设计

### 5.1 MySQL（元数据存储）

```sql
CREATE TABLE t_book (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    title           VARCHAR(256)    NOT NULL,
    author          VARCHAR(128)    NOT NULL,
    isbn            VARCHAR(32)     NOT NULL UNIQUE,
    category        VARCHAR(64),
    description     TEXT,
    page_count      INT             NOT NULL DEFAULT 0,
    cover_url       VARCHAR(512),
    content_url     VARCHAR(512),       -- S3 正式区 EPUB 文件路径
    original_url    VARCHAR(512),       -- S3 原始文件路径（保留备份）
    preview_url     VARCHAR(512),       -- 预留，可扩展
    status          VARCHAR(32)     NOT NULL DEFAULT 'PROCESSING',  -- PROCESSING/ON_SHELF/OFF_SHELF
    rating          DOUBLE          DEFAULT 0.0,
    review_count    INT             NOT NULL DEFAULT 0,
    borrow_count    INT             NOT NULL DEFAULT 0,
    hot_score       INT             NOT NULL DEFAULT 0,
    published_date  DATE,
    created_at      DATETIME        NOT NULL,
    updated_at      DATETIME        NOT NULL
);
```

**职责**：仅存储书籍元数据和 S3 文件路径，不存储书籍内容。

### 5.2 S3（文件存储）

```
s3://elibrary-books/
├── original/                    # 原始文件备份区
│   └── {bookId}/
│       └── original.pdf         # 管理员上传的原始文件
│
├── epub/                        # 转码后的 EPUB 正式区
│   └── {bookId}/
│       └── book.epub            # 转码完成的 EPUB 文件
│
└── temp/                        # 转码临时区（定时清理）
    └── {taskId}/
        ├── upload.pdf           # 待转码的原始文件
        └── converted.epub       # 转码中间产物
```

**生命周期策略**：
- `temp/` 目录：设置 24 小时自动过期删除
- `original/` 目录：永久保留（用于重新转码或审计）
- `epub/` 目录：永久保留

## 6. 异步任务设计

### 6.1 任务状态机

```
PENDING → PROCESSING → SUCCESS / FAILED
   │          │           │         │
   │          │           │         └─→ 记录失败原因，通知管理员
   │          │           └─→ 更新书籍状态为 ON_SHELF
   │          └─→ Worker 正在转码
   └─→ 任务已入队，等待 Worker 消费
```

### 6.2 任务消息结构

```json
{
  "taskId": "task-20240101-001",
  "bookId": 123,
  "originalS3Key": "temp/task-20240101-001/upload.pdf",
  "epubS3Key": "epub/123/book.epub",
  "originalS3KeyBackup": "original/123/original.pdf",
  "fileType": "pdf",
  "createdAt": "2024-01-01T10:00:00"
}
```

### 6.3 Worker 处理流程

```java
@Component
public class BookConversionWorker {

    @RabbitListener(queues = "book.conversion")
    public void handle(BookConversionTask task) {
        // 1. 更新任务状态为 PROCESSING
        taskRepository.updateStatus(task.getTaskId(), "PROCESSING");

        try {
            // 2. 从 S3 下载原始文件到本地临时目录
            Path localFile = s3Service.downloadToTemp(task.getOriginalS3Key());

            // 3. 根据文件类型选择转码路径
            Path epubFile;
            String fileType = task.getFileType();
            if ("doc".equals(fileType) || "docx".equals(fileType)) {
                // DOC/DOCX → PDF → EPUB
                Path pdfFile = libreOfficeService.convertToPdf(localFile);
                epubFile = calibreService.convertToEpub(pdfFile);
            } else {
                // TXT/EPUB/PDF → EPUB
                epubFile = calibreService.convertToEpub(localFile);
            }

            // 4. 上传 EPUB 到 S3 正式区
            s3Service.upload(epubFile, task.getEpubS3Key());

            // 5. 备份原始文件到 S3
            s3Service.upload(localFile, task.getOriginalS3KeyBackup());

            // 6. 提取前 5% 内容 + 元数据 → 写入 ES
            BookPreview preview = epubExtractor.extractPreview(epubFile, 0.05);
            elasticsearchService.indexBookPreview(task.getBookId(), preview);

            // 7. 更新 MySQL 书籍状态
            bookService.updateBookStatus(task.getBookId(), BookStatus.ON_SHELF);
            bookService.updateContentUrl(task.getBookId(), task.getEpubS3Key());

            // 8. 更新任务状态为 SUCCESS
            taskRepository.updateStatus(task.getTaskId(), "SUCCESS");

        } catch (Exception e) {
            // 9. 记录失败原因
            taskRepository.updateStatus(task.getTaskId(), "FAILED");
            taskRepository.updateErrorMessage(task.getTaskId(), e.getMessage());
            log.error("书籍转码失败: bookId={}", task.getBookId(), e);
        } finally {
            // 10. 清理本地临时文件
            cleanupTempFiles(task);
        }
    }
}
```

## 7. 分布式事务处理

### 7.1 问题分析

书籍上传涉及三个存储系统：
- **MySQL**：书籍元数据
- **S3**：EPUB 文件
- **Elasticsearch**：预览内容

这三个系统无法用传统的 `@Transactional` 保证一致性。

### 7.2 方案对比

| 方案 | 优点 | 缺点 | 适用性 |
|------|------|------|--------|
| 2PC/XA | 强一致性 | 性能差、实现复杂、ES 不支持 | ❌ 不适用 |
| Seata AT | 对业务代码侵入小 | 需要额外部署 Seata Server、ES/S3 不支持 | ❌ 不适用 |
| **本地消息表 + 最终一致性** | 实现简单、各系统独立、容错性好 | 需要处理消息重试、幂等 | ✅ **推荐** |
| Saga 模式 | 适合长事务 | 实现复杂、需要补偿逻辑 | ⚠️ 过度设计 |

### 7.3 最终方案：本地消息表 + 最终一致性

```
┌─────────────────────────────────────────────────────────────────┐
│                     上传请求 (同步)                               │
│                                                                 │
│  1. BEGIN TRANSACTION                                           │
│  2. INSERT INTO t_book (元数据, status=PROCESSING)              │
│  3. INSERT INTO t_task (任务消息)                               │
│  4. COMMIT TRANSACTION  ← MySQL 保证这两条记录的原子性            │
│  5. 上传原始文件到 S3 临时区                                      │
│  6. 返回 "处理中" 响应                                           │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                   异步 Worker (最终一致性)                         │
│                                                                 │
│  1. 消费任务消息                                                 │
│  2. 执行转码                                                     │
│  3. 上传 EPUB 到 S3 正式区                                       │
│  4. 写入 ES 预览内容                                             │
│  5. 更新 MySQL 书籍状态 = ON_SHELF                               │
│  6. 更新任务状态 = SUCCESS                                       │
│  7. 删除 S3 临时文件                                             │
│                                                                 │
│  如果任何步骤失败：                                               │
│  - 更新任务状态 = FAILED                                         │
│  - 记录错误原因                                                  │
│  - 不删除临时文件（保留排查）                                     │
│  - 定时任务重试（最多 3 次）                                      │
└─────────────────────────────────────────────────────────────────┘
```

**一致性保证**：
- MySQL 内的书籍记录和任务消息在同一事务中，保证原子性
- S3 和 ES 的操作通过异步任务最终完成，保证最终一致性
- 如果 Worker 失败，定时任务会重试；超过重试次数后告警通知管理员
- 如果 S3 上传成功但 ES 写入失败，Worker 会重试 ES 写入（幂等操作）

## 8. 阅读鉴权设计

### 8.1 鉴权拦截器

```java
@Component
public class ReadingAuthInterceptor implements HandlerInterceptor {

    private final BorrowRecordRepository borrowRecordRepository;
    private final BookAccessConfigRepository accessConfigRepository;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        Long userId = AuthContext.getCurrentUserId();
        Long bookId = extractBookId(request);

        // 1. 检查是否有活跃借阅
        Optional<BorrowRecord> activeBorrow = borrowRecordRepository
                .findByUserIdAndBookIdAndStatus(userId, bookId, BorrowStatus.ACTIVE);

        if (activeBorrow.isPresent() && activeBorrow.get().getDueDate().isAfter(LocalDateTime.now())) {
            // 已借阅 → 放行，标记为 FULL_ACCESS
            request.setAttribute("accessLevel", "FULL");
            return true;
        }

        // 2. 检查是否允许预览
        BookAccessConfig config = accessConfigRepository.findByBookId(bookId)
                .orElse(null);
        if (config != !config.getAccessType().equals("PAID")) {
            // 免费书籍 → 放行，标记为 PREVIEW_ONLY
            request.setAttribute("accessLevel", "PREVIEW");
            return true;
        }

        // 3. 付费书籍且未借阅 → 返回 403
        response.setStatus(HttpStatus.FORBIDDEN.value());
        response.setContentType("application/json");
        response.getWriter().write("{\"code\":403,\"message\":\"请先借阅或购买后再阅读\"}");
        return false;
    }
}
```

### 8.2 阅读内容返回策略

```java
@RestController
@RequestMapping("/api/reading")
public class ReadingController {

    @GetMapping("/{bookId}/content")
    public ResponseEntity<?> getBookContent(
            @PathVariable Long bookId,
            HttpServletRequest request) {

        String accessLevel = (String) request.getAttribute("accessLevel");

        if ("FULL".equals(accessLevel)) {
            // 已借阅 → 返回完整 EPUB 的 S3 预签名 URL（有效期 2 小时）
            String epubUrl = s3Service.generatePresignedUrl(
                    "epub/" + bookId + "/book.epub", Duration.ofHours(2));
            return ResponseEntity.ok(Map.of("url", epubUrl, "accessLevel", "FULL"));
        }

        if ("PREVIEW".equals(accessLevel)) {
            // 预览 → 返回 ES 中的前 5% 内容
            BookPreview preview = elasticsearchService.getBookPreview(bookId);
            return ResponseEntity.ok(Map.of(
                    "content", preview.getPreviewContent(),
                    "chapters", preview.getPreviewChapters(),
                    "accessLevel", "PREVIEW",
                    "previewPercent", 5
            ));
        }

        return ResponseEntity.status(HttpStatus.FORBIDDEN)
                .body(ApiResponse.error(403, "请先借阅或购买后再阅读"));
    }
}
```

### 8.3 客户端 epub.js 集成

async function loadBook(bookId) {
    const response = await fetch(`/api/reading/${bookId}/content`, {
        headers: { 'Authorization': `Bearer ${token}` }
    });

    if (response.status === 403) {
        showPaywall();  // 显示借阅/购买弹窗

    const data = await response.json();

    if (data.accessLevel === 'FULL') {

        book.renderTo('viewer');

        renderPreview(data.content, data.chapters);
        showPreviewLimitNotice();  // 显示"已到达预览末尾，请借阅"提示
    }
}

## 10. 关键配置

### 10.1 线程池配置

```java
@Configuration
public class ConversionThreadPoolConfig {

    @Bean("conversionExecutor")
    public Executor conversionExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(2);          // Calibre 转码是 CPU 密集型，核心数不宜过多
        executor.setMaxPoolSize(4);
        executor.setQueueCapacity(20);
        executor.setThreadNamePrefix("conversion-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        return executor;
    }
}
```

### 10.2 Calibre 配置

## 12. 扩展性设计

| 扩展方向 | 实现方式 |
|----------|----------|
| 新增支持格式 | 在 Worker 中新增文件类型判断分支，无需改核心流程 |
| 新增转码工具 | 实现 `ConversionService` 接口，注入 Worker |
| 多实例 Worker | 通过消息队列实现负载均衡，天然支持水平扩展 |
| 预览比例调整 | 从 Nacos 动态配置 `elibrary.preview.percent`，无需重启 |
| 全文搜索增强 | ES 中增加字段、调整分词器，不影响 MySQL 和 S3 |
